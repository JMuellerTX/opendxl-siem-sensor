# OCSF Mapping: OpenDXL SIEM Sensor

This document describes the mapping of OpenDXL events to the Open Cybersecurity Schema Framework (OCSF) version 1.x. The sensor normalizes raw events from the DXL protocol into standardized OCSF classes to ensure seamless integration into modern SIEM solutions.

## Mapping Summary

All emitted events share common required OCSF attributes such as `time`, `severity_id`, `severity`, and `metadata` (`metadata.product.name = "Rust SIEM Sensor"`, `metadata.product.vendor_name = "OpenDXL"`).

| DXL Event | OCSF Class | Class UID | Activity | Activity ID | Type UID |
|-----------|------------|-----------|----------|-------------|----------|
| `clientregistry/connect` | Network Activity | 4001 | Connect | 1 | 400101 |
| `clientregistry/disconnect` | Network Activity | 4001 | Disconnect | 2 | 400102 |
| `svcregistry/register` | API Activity | 6003 | Create | 1 | 600301 |
| `svcregistry/unregister` | API Activity | 6003 | Delete | 4 | 600304 |
| Synthetic Alerts | Detection Finding | 2004 | Create | 1 | 200401 |

## 1. Network Activity (Class UID: 4001)

Used for client connections and disconnections to/from the broker (`clientregistry/connect`, `clientregistry/disconnect`).

**Rationale for Class Selection:**
Connect and Disconnect events represent the establishment and termination of TCP/TLS connections to the MQTT broker. The `Network Activity` class covers this type of network traffic and provides dedicated attributes for transport and encryption details.

**Relevant OCSF Attributes:**
*   `activity_id`: `1` (Connect), `2` (Disconnect)
*   `client_guid` (Custom Field): The DXL Client Instance GUID.
*   `connection_info.protocol_name`: `mqtt` or `websocket` (if reported by the broker).
*   `src_endpoint.ip`: The IP address of the requesting client (IPv4-mapped addresses are cleaned).
*   `tls.version`: The negotiated TLS version (e.g., `TLSv1.3`).
*   `tls.cipher_suites`: The negotiated IANA cipher suite (e.g., `TLS_AES_256_GCM_SHA384`).
*   `tls.certificate.fingerprint`: The SHA-1 thumbprint of the client certificate.

## 2. API Activity (Class UID: 6003)

Used for the registration and deregistration of OpenDXL services (`svcregistry/register`, `svcregistry/unregister`).

**Rationale for Class Selection:**
Registering a service in the DXL fabric closely resembles an API call for resource creation, and unregistering resembles resource deletion. "API Activity" represents interactions with services and their lifecycle methods (Create/Delete) very well, whereas "Application Lifecycle" is more suited for describing the state of local applications.

**Relevant OCSF Attributes:**
*   `activity_id`: `1` (Create) for `register`, `4` (Delete) for `unregister`.
*   `api.service.uid`: The unique `serviceGuid` of the service.
*   `api.service.name`: The name or type of the service (`serviceType`, e.g., `/mcafee/service/tie/file/reputation`).
*   `actor.user.uid`: The SHA-1 thumbprint of the registering service client (if transmitted in the register event).

## 3. Detection Finding (Class UID: 2004)

Used for all anomalies (detections) generated by the sensor itself.

**Rationale for Class Selection:**
The sensor acts as a security analytics component. Synthetic alerts like "Unknown Thumbprint" or "Legacy Cipher Suite" represent concrete security findings, for which the `Detection Finding` class is intended.

**Relevant OCSF Attributes:**
*   `activity_id`: `1` (Create)
*   `finding_info.title`: Name of the detection (e.g., "Legacy Cipher Suite").
*   `finding_info.desc`: Description and context of the alert.
*   `suser`: Optional; contains the certificate thumbprint of the involved client.
*   `severity_id`: Defaults to `4` (High).
